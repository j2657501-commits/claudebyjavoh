# Ассеты: генерация по частям

Принцип: **ИИ рисует, код управляет.** Генератор отвечает за форму, материал и стиль одного куска. Масштаб, свет, глубину, дымку, тени, обводку, движение и эффекты делает код. Тогда набор выглядит единым, а сцена — живой.

## 1. Маршруты генерации
| Маршрут | Когда | Как |
|---|---|---|
| **MCP `codex-image`** (по умолчанию) | Есть Codex CLI и вход через ChatGPT | `claude mcp add --scope user codex-image -- python3 <skill>/scripts/codex_image_mcp.py`. Инструменты: `image_generate`, `image_parts`, `image_job`, `image_check` |
| Скилл ref2game (если установлен) | Нужен полный пайплайн: пакеты, слайсинг, ключевание, риг | его `gen.py batch jobs.json` |
| Веб-генератор пользователя | Нужны другие модели (GPT-image, Nano Banana, Flux и т. п.) | Открыть сервис в браузере пользователя с его разрешения, приложить каноничный референс, сохранить результат в `art/raw/`. Его кредиты тратятся только с согласия |
| Свой генератор пользователя | Пользователь назвал сервис | Изучить документацию, подключить узким скриптом, один пробный вызов, бюджет — по согласию |
| Вручную | Нет доступа | Ты пишешь промпты, пользователь кладёт картинки в `art/raw/` |

Всё, что сгенерировано, лежит в проекте: `art/raw/` (как пришло), `art/gen/` (обработано), `art/prompts/` (тексты), `art/style_bible.txt`.

## 2. Порядок (не менять)
1. **Библия стиля** `art/style_bible.txt`: 6–10 строк.
   - материал и техника;
   - линия;
   - палитра (hex);
   - направление света;
   - фактура и зерно;
   - что запрещено.

   Она идёт дословно в **каждый** вызов.
2. **Каноничный референс героя:** одна картинка в нейтральной позе, анфас или ¾, руки и ноги не перекрывают тело. Её утверждают первой, и дальше она прикладывается к **каждому** вызову. Никогда не генерируй следующий кадр по предыдущей перегенерации: накапливается дрейф.
3. **Части куклы** (`image_parts`, `kind: "part"`, `transparent: true`): по одной части на вызов, одинаковый масштаб и ракурс. Типовой набор:
   - гуманоид: `head`, `torso`, `pelvis`, `upper_arm_l/r`, `forearm_l/r`, `hand_l/r` (+ 2–3 позы кисти), `thigh_l/r`, `shin_l/r`, `foot_l/r`, `mouth_0..4`, `eyes_open/closed`, `brow`;
   - животное: + `neck`, `tail_1..3`, `ear_l/r`;
   - объект: `lid`, `body`, `door`, `wheel`, `screen`, `button_up/down`.
4. **Слои глубины** (`kind: "plate"`): `sky`, `far`, `back`, `action_bg`, `near_props`, `lens_debris`. Каждый слой содержит только своё; всё, что ближе, прозрачно. Запас 25 % по краям под движение камеры.
5. **Бутафория:** отдельные объекты, которые будут реагировать (качаться, падать, открываться), каждый со своей альфой.
6. **Лист частей одной картинкой** (быстрее, если генератор держит раскладку). Пример промпта:
   ```
   Flat 2D orthographic part sheet of [hero] on a plain transparent background. Neutral pose, every part drawn as its own separate piece with ≥5% empty gap: head, torso, pelvis, upper arm, forearm, hand ×2 (open and gripping), thigh, shin, foot, [tail/ears]. Draw each piece complete, including the end normally hidden by the next piece (round it). Same line weight and palette as the reference. No shadows, no text, no labels, no cropping.
   ```
   Нарежь лист на части по альфе (любым скриптом: связные области альфа-канала → отдельные PNG; или `slice.py` из ref2game, если он есть). Отдельно генерируй сетку 3×3 из 9 форм рта.
7. **Проверка** (`image_check` + взгляд):
   - внешнее кольцо в 1 px полностью прозрачное;
   - полупрозрачных пикселей ≤ 8 %;
   - край не тянет к цвету фона;
   - поля ≥ 2 px.
   - настоящая альфа;
   - непрозрачная рамка < 5 %;
   - ореол на тёмном и светлом фоне;
   - одинаковое направление света и толщина линии во всём наборе;
   - суставы с запасом.

   Брак перегенерируй с тем же референсом и уточнением, а не «похожим новым».
8. **Сборка:** части → риг (`references/rigs.md`), слои → `DEPTH25`, бутафория → физика или пружины.

## 3. Шаблоны промптов
**Часть куклы:**
```
ASSET: the LEFT FOREARM of <hero> from the reference: from elbow to wrist, straight, neutral, seen from the same 3/4 front camera,
same line weight and paper texture; elbow end extended with a rounded joint cap (~15% overlap); nothing else in the image.
```

**Слой глубины:**
```
ASSET: MID layer of <scene>: harbour cranes and warehouses at dusk, continuous wide strip, horizon at 60% height,
sky and everything in front left transparent; warm key light from the left as in the style bible.
```

**Бутафория:**
```
ASSET: a single ceramic cup, isolated, 3/4 view, light from the left, soft contact shadow excluded (code draws it).
```

**Текстура для кода:**
```
ASSET: seamless tileable fine-grain texture matching the style bible, no objects, even lighting.
```

**Чего избегать:**
- «красивая картинка с персонажем в динамичной позе» (это не часть, её не заригать);
- тени и пол на прозрачных частях;
- текст внутри картинки (текст делает код);
- шахматка вместо альфы.

## 4. Альфа и края
- PNG должен иметь настоящий альфа-канал. Нарисованная шахматка или однотонный фон — это не прозрачность.
- Если генератор не умеет альфу: генерируй на ровном ключевом цвете (`#00FF00` или контрастном к палитре), снимай ключ скриптом (ref2game `gen.py key`), проверяй ореол.
- Premultiplied alpha в браузере: края должны быть чистыми на тёмной и светлой подложке.

## 5. Готовые 3D-модели
| Источник | Что брать | Условия |
|---|---|---|
| Poly Haven (polyhaven.com/models) | реалистичные предметы, HDRI, текстуры | CC0, glTF, без регистрации |
| Kenney (kenney.nl/assets) | стилизованные наборы: город, транспорт, интерьер | CC0, GLB |
| Quaternius (quaternius.com) | персонажи с ригом и анимациями, low-poly миры | лицензия конкретного выпуска; модели нельзя раздавать отдельно |
| Poly Pizza (poly.pizza) | low-poly объекты | лицензия у модели (CC0/CC-BY); не качать автоматически пачками |
| Sketchfab (sketchfab.com) | конкретные устройства, сложные объекты | только Downloadable + CC0/CC-BY; нужен аккаунт пользователя |

Модель после загрузки:
- нормализуй масштаб, оси и pivot;
- проверь текстуры и материал;
- сократи тяжёлые меши;
- поставь свет под стиль сцены.

У составных объектов (ноутбук, дверь) должны быть отдельные части и оси шарниров. В конце ролика укажи источник, автора и лицензию.
